> 用途：**一页看清「现在到底有哪些测试、各验什么、缺口在哪」**。
> 设计意图与用例推导 → `docs/测试方案.md`；执行过程与踩坑记录 → `docs/测试报告.md`。
> 数据截至 2026-10-27（`e9b7780`），数字均按源码实际统计，非估算。

## 1. 结论先行

| 层 | 数量 | 运行位置 | 状态 |
|---|---|---|---|
| 后端单元测试 | **427 个 / 34 类** | 本地 + CI `backend-unit` | 全绿（约 14 秒） |
| 后端集成测试 | **16 个 / 7 类** | 本地 + CI `backend-integration` | 全绿（约 52 秒） |
| 前端 E2E | **3 个 / 2 文件** | 本地 + CI `e2e` | 全绿（约 16 秒） |

**一句话**：后端「逻辑层」和「真实中间件层」都有覆盖，前端只有端到端没有单测；
六道质量闸门（G1~G6）已全部落地，5 次变异验证全部被抓住。

## 2. 后端单元测试（427 个 / 34 类）

全部是 Mockito 单测，不起容器，秒级反馈。按模块分布：

| 模块 | 用例 | 类数 | 重点覆盖 |
|---|---|---|---|
| **trade** | 105 | 5 | 下单主流程、支付回调、库存扣减/回补、订单状态机、超时消息消费 |
| **product** | 101 | 5 | 商品 CRUD、SKU 增量同步、分类树、收藏、浏览记录、库存预警线解析 |
| **seckill** | 76 | 5 | 活动 CRUD 与重叠校验、库存预热与原子扣减、异步建单、结果查询、状态机 |
| **common** | 41 | 7 | 缓存读写与降级、限流、幂等、文件存储、统一响应、全局异常 |
| **auth** | 35 | 4 | 登录/注册/刷新令牌、密码策略、短信频控、登录失败锁定 |
| **cart** | 30 | 1 | 加购/改量/勾选/失效商品处理 |
| **search** | 25 | 5 | 搜索日志缓冲、同义词、词项抽取、日志清理任务 |
| **member** | 14 | 1 | 收货地址增删改查与默认地址唯一性 |

单类用例数 TOP 5：`OrderServiceTest`(70)、`ProductServiceTest`(57)、
`SeckillActivityServiceTest`(42)、`CartServiceTest`(30)、`AuthServiceTest`(23)。

**这一层的价值与局限**：能挡住「正常路径的逻辑写错」，但被 mock 掉的恰好是幂等、
超卖、MQ 可靠性依赖的**真实中间件行为**——所以它绿了不代表系统不会超卖，那要靠集成测试。

## 3. 后端集成测试（16 个 / 7 类）

Testcontainers 起真实 MySQL / Redis / RabbitMQ，直接打 HTTP（MockMvc），走完整过滤链。

| 类 | 用例 | 闸门 | 验什么 |
|---|---|---|---|
| `OrderIdempotentIT` | 1 | G2 并发 | 同一幂等键**并发 50 次**，只产生 1 张订单 |
| `OrderOversellIT` | 1 | G2 并发 | 库存 10 / **并发 100**，成功恰好 10 件，库存归零不超卖 |
| `OrderTimeoutIT` | 2 | G3 异步 | 超时消息 → 关单 + 回补库存；**重复投递只生效一次** |
| `AuthorizationIT` | 7 | G4 权限 | 横向越权 3 条 + 401/403 各 1 条 + **管理员正向对照 1 条** |
| `HistoricalRegressionIT` | 3 | G6 回归 | 支付流水展示、秒杀活动时间重叠（含首尾相接边界） |
| `ContextSmokeIT` | 1 | 冒烟 | Spring 上下文可加载、Flyway 迁移成功 |
| `ContainerSmokeIT` | 1 | 环境 | 容器能起、SQL 能通（换机器先跑它） |

三个设计要点：

1. **每个用例结束自动跑不变量检查**（`InventoryInvariantChecker`）：库存汇总账 = SKU 合计、
   非负、不超备货。G1 不是独立用例，是**横向约束**，挂在所有写库存的用例上。
2. **权限测试必须走 MockMvc**：越权拦截在 Filter + SecurityConfig 层，直调 Service 测不到。
   且**必须有正向对照**（管理员访问 `/api/admin/**` = 200），否则 `denyAll` 也能让负向全绿。
3. **超时关单不靠改 TTL 等时间**：队列参数冲突，改为直接往 `trade.dlx` 投消息，
   绕开「等 N 分钟」，把测试从分钟级压到秒级。

## 4. 前端 E2E（3 个 / 2 文件）

Playwright + 系统 Chrome（`channel: 'chrome'`，跳过 130MB 下载，CI 也不用装浏览器）。

| 文件 | 用例 | 覆盖 |
|---|---|---|
| `order-flow.spec.ts` | 1 | 登录 → 搜索 → 详情 → 加购 → 购物车 → 结算 → 提交 → 去支付 → 确认付款 → 订单列表可见 |
| `smoke.spec.ts` | 2 | 首页渲染出商品列表；搜索能返回结果 |

`order-flow` 里带一条**回归断言** `expect(page.locator('.van-tabbar')).toBeHidden()`，
防止有人把 `checkout` 从 `TabBarLayout.FULLSCREEN_ROUTES` 白名单里删掉（删了提交按钮会被 tabbar 压住）。

**这层抓到了集成测试永远抓不到的 bug**：地址异步加载未完成时点「提交订单」直接 `return`，
只弹一个 1.5 秒消失的 toast，页面纹丝不动——直调 `OrderService` 的测试根本不经过这一层。
现已把地址加载态拆成「加载中 / 无地址 / 就绪」三种，按钮分别 `loading+disabled` / `disabled` / 可点。

## 5. 手工验证脚本（5 个，不进 CI）

需要真实后端 + 中间件，且要关限流（`RATE_LIMIT_ENABLED=false`），所以不进 CI。

| 脚本 | 验什么 |
|---|---|
| `verify-order-idempotent.mjs` | A1 下单幂等 + 结算抢占（可配并发数） |
| `verify-seckill-stock.mjs` | B2 秒杀库存原子扣减，不超卖、不超限购 |
| `verify-seckill-order.mjs` | B3 端到端：抢购 → MQ → 消费者建单 → 结果查询 → 取消回补 |
| `bench-seckill.mjs` | 秒杀压测：QPS / P95 / 成功率 / 是否超卖 |
| `seed-bench-users.mjs` | 压测账号准备（限购 1 件/人 + 3 秒请求锁 → N 并发需 N 个账号） |

## 6. 六道闸门映射

| 闸门 | 验的是什么 | 落地位置 | 用例 |
|---|---|---|---|
| G1 数据不变量 | 库存汇总账、非负、不超备货 | `InventoryInvariantChecker`（横向） | 随每个写库存用例自动跑 |
| G2 并发 | 下单幂等、防超卖 | `OrderIdempotentIT` / `OrderOversellIT` | 2 |
| G3 异步 | 超时关单、重复消费幂等 | `OrderTimeoutIT` | 2 |
| G4 权限 | 横向越权、认证、授权 | `AuthorizationIT` | 7 |
| G5 用户旅程 | 浏览器里跑完整下单链路 | `frontend/e2e/` | 3 |
| G6 历史回归 | 已修 bug 不复发 | `HistoricalRegressionIT` | 3 |

**测试有效性（变异验证）：5 / 5 全部被抓住**——故意改坏幂等键校验、库存扣减条件、
权限拦截、超时幂等、支付流水排序，五次全部有测试报警。这比用例数量更能说明问题。

## 7. 覆盖缺口与未完成项

| # | 项 | 性质 | 影响 |
|---|---|---|---|
| 1 | **前端零单元测试**（无 vitest） | 缺口 | 组件/工具函数逻辑只能靠 E2E 兜，成本高、覆盖薄 |
| 2 | **秒杀链路故障注入未实测** | 未完成 | 3 场活动都已结束，构造不出真实扣减场景；按代码分析 `tryDeduct` 无 catch → 500 且不超卖 |
| 3 | **Redis 降级「成功但不可用」** | 已识别未修 | 超时 `3s`，读+写各超时一次 → 单请求 6 秒（正常 0.019s）。并发一高就占满线程池。修法：超时调至 500ms 或加熔断器 |
| 4 | **MQ 挂掉无兜底补偿** | 已知取舍 | 下单照常成功（200/0.17s），但超时消息丢失 → 订单永停「待付款」、库存永被占用。补一个低频扫「创建超 N 分钟未支付」的任务即可 |
| 5 | **E2E 无数据隔离** | 已知限制 | 直写开发库、扣真实库存；失败残留购物车，反复跑会累积消耗库存 |
| 6 | **3 个 UI 校验脚本失效** | 未修 | `tab-slide-verify`(2)、`tab-direction-verify`(4)、`auth-gate-verify`(1) 仍按 **3 个 tab** 的索引点 tabbar，秒杀改成第 2 个页签后 index 对不上。断言逻辑本身没问题，只是选择器过时 |

第 3、4 项是「故障注入实测推翻代码预判」的产物，属于**可用性问题**而非数据正确性问题，
优先级低于第 1、6 项。

## 8. 怎么跑

```bash
# 一键跑与 CI 完全一致的三件事（需要 Docker）
bash scripts/verify.sh
#   1/3 后端单元测试   427 个 / 约 14 秒
#   2/3 后端集成测试    16 个 / 约 50 秒
#   3/3 前端双端类型检查 + 构建

# 单独跑
cd backend && mvn -B test                              # 只跑单测
cd backend && mvn -B test -Dtest='*IT'                 # 只跑集成测试（★IT 类名不能以 Test 开头）
cd frontend && pnpm e2e                                # E2E（需 8080 后端 + 5173 前端已启动）

# 换机器 / 升级 Docker 后先验证环境（12 秒）
cd backend && mvn -B test -Dtest='ContainerSmokeIT'
```

CI 配置见 `.github/workflows/ci.yml`，push / PR 自动触发，4 job 并行。

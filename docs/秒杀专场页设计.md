## 2. 一个必须先补的后端小改动：剩余库存口径

`GET /api/seckill/activities` 现在返回的 `remainingStock` 是 **DB 口径**
（`seckill_stock - sold_count`），而 `sold_count` 只在**消费者建单成功后**才累加。

后果：抢购高峰时，前台进度条会明显滞后 —— 用户看到「还剩 30 件」，实际 Redis 早就 0 了，
点进去全是「已抢光」。

**改法**：列表与详情接口读 `seckill:stock:{id}` 填充 `remainingStock`（Redis 才是权威）。
Redis 里没有（未预热/已过期）时回退到 DB 口径。

这是 B2 设计里「B2 之后前台展示以 Redis 为准」那句话的落地，只是当时没做。

### 3.1 地址栏（页面级，不是卡片级）

地址是「本次抢购寄到哪里」，属于页面级状态，放在列表**上方常驻**，
而不是塞进抢购弹层里 —— 用户一进页面就能看到、能改。

| 状态 | 展示 | 点击行为 |
|---|---|---|
| 未选择 | 📍 `请选择收货地址`（灰色）+ 右箭头 | 打开地址选择弹层 |
| 已选择 | 📍 收件人 + 脱敏手机号 + 完整地址 + 右箭头 | 打开地址选择弹层**修改** |
| 一个地址都没有 | 📍 `请添加收货地址` + 右箭头 | 直接跳「收货地址」页 |

细节：

- **手机号脱敏**：`138****8000`，与结算页口径一致。
- **初始选中**：进入页面时若有默认地址则自动选中，没有则停在「请选择收货地址」。
- **不跨页面记忆**：离开秒杀页再回来，重新按默认地址初始化 —— 秒杀是「当下这一次」的选择，
  记住上次容易让人以为改过了。
- 选择弹层复用结算页（`CheckoutView`）的底部弹层模式（`.addr-popup`，`position="bottom"`）；
  若两处样式完全一致，抽成 `components/AddressPickerSheet.vue` 共用，避免抄两遍。

### 3.2 商品卡片按钮状态机

| 活动状态 | 库存 | 按钮 |
|---|---|---|
| 即将开始 | — | 「xx:xx 开抢」（禁用，本地倒计时） |
| 进行中 | > 0 | 「立即抢购」（可点） |
| 进行中 | 0 | 「已抢光」（禁用） |
| 已结束 | — | 「已结束」（禁用） |

> 「用户已抢」这一态在 B4 **不做本地持久化**：抢购成功后直接跳订单详情，
> 用户回来时页面重新拉列表，靠限购在后端拦住重复购买（第二次点会拿到 409「每人限购」）。

## 4. 抢购交互

```
点击「立即抢购」
  ├─ 未登录        → 跳登录（带 redirect 回秒杀页）
  ├─ 未选择地址    → toast「请选择收货地址」+ 地址栏高亮提示，**不发请求**
  └─ 已选地址 →
       ① 底部确认弹层：商品图 / 名称 / 秒杀价 / 数量 / 收货地址（**只读展示**）
       ② 点「确认抢购」→ 按钮 loading，立即禁止再次点击
       ③ POST /api/seckill/{id}/order { quantity, addressId }
       ④ 成功拿到 requestId → 轮询结果
       ⑤ SUCCESS → 跳订单详情（带 from=seckill）
          FAILED → toast 原因 + 刷新该活动剩余库存
```

要点：

- **地址在页面选，弹层只做确认**：弹层里再放一个地址选择器会与页面上的地址栏重复，
  用户会疑惑「以哪个为准」。
- 确认弹层仍然保留，是为了让用户在最后一刻看清「买的是什么、寄到哪里」，
  避免误触直接扣掉一次限购名额。
- **防连点**：`submitting` 置位后按钮 disabled；即使绕过前端，后端还有 3 秒请求锁。
- **未选地址不弹确认层**：直接提示并聚焦地址栏，少一次无意义的弹层开合。

## 5. 结果轮询策略

```
第 1 次：200ms 后
第 2 次：400ms
第 3 次：800ms
第 4 次：1600ms
之后：每 2000ms 一次，直到 15 秒总超时
```

- 用**指数退避 + 上限**，而不是固定 500ms 猛刷：绝大多数订单在 1 秒内建好，
  退避能让 90% 的请求在 3 次内结束。
- 15 秒超时后提示「仍在排队，可稍后在订单列表查看」，并停止轮询 ——
  不能无限轮询，否则用户挂着页面就在烧请求。
- 组件卸载或失活时清掉定时器（`onUnmounted` / `onDeactivated`），避免后台页面继续打接口。

## 7. 倒计时的时区问题

后端返回的 `startTime` / `endTime` 是**不带时区**的 `LocalDateTime`（如 `2026-10-19T18:00:00`）。
浏览器 `new Date('2026-10-19T18:00:00')` 按**本地时区**解析 —— 与服务端同机同区时正确。

局限：用户改系统时间或跨时区访问会偏。但**倒计时只是展示**，
真正的准入判断在服务端（抢购时校验 `startTime/endTime`），所以偏了也不会越权抢。

> 如果以后要做多时区，接口需要额外返回 `serverTime`，前端算 offset 再展示。
> 当前单机单时区部署，不做。

## 8. 验收标准

| 场景 | 期望 |
|---|---|
| 首次进入（有默认地址） | 地址栏显示默认地址；无默认则显示「请选择收货地址」 |
| 点击地址栏 | 弹出地址选择，选中后地址栏立即更新 |
| 一个地址都没有 | 地址栏显示「请添加收货地址」，点击直接进地址页 |
| 未选地址点抢购 | toast「请选择收货地址」，**不发出抢购请求** |
| 未开始的活动 | 按钮显示倒计时且禁用，到点自动变「立即抢购」 |
| 进行中且库存充足 | 确认层 → 抢购成功 → 跳订单详情 |
| 库存耗尽 | 按钮变「已抢光」，进度条 100% |
| 抢购失败（限购/售罄） | toast 原因，刷新库存 |
| 轮询超时 | 提示「仍在排队」，停止轮询 |
| 重复点击 | 按钮 loading，只发一次请求 |

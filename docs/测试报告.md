### P0 结论与发现

**1. 后端基线是绿色的，428 个用例全过。** 后续任何失败都可以判定为新引入的回归，基线可信。

**2. 但「全绿」的含义有限。** 这 428 个用例全部是 Mockito 单测，被 mock 掉的恰好是幂等、超卖、MQ 可靠性这三套核心机制依赖的真实中间件行为（详见 `docs/测试方案.md` §1.2）。基线绿只说明「正常路径的代码逻辑没坏」，不说明「系统不会超卖」。

**3. 前端构建链路目前是断的（P0 最重要的发现）。**

`apps/*/package.json` 的 `build` 脚本是：

```json
"build": "vue-tsc --noEmit && vite build"
```

`vue-tsc` 非零退出会直接中断 `build`。也就是说**当前前端无法构建，也就无法部署**——这不是「测试不通过」，是上线阻塞项。

两处修复成本都很低：

- `request.ts`：拦截器把 `response` 转成 `response.data` 后返回，类型签名与 Axios 期望的 `AxiosResponse` 不符。给拦截器加正确的泛型标注，或改成 `(response) => response.data as T` 后强转。
- `vite.config.ts`：`pnpm --filter mall add -D @types/node` 即可（admin 同理）。

**建议在进入 P1 之前先修掉**，否则后续 CI 里的 `vue-tsc` 永远红，闸门形同虚设。这也符合「功能未稳定不做全局美化」的反面——类型检查属于功能正确性，不是美化。

**4. 测试基础设施已就绪。** `TestcontainersSmokeTest` 保留在代码库中，换机器或升级 Docker 后先跑它验证环境（12 秒），避免集成测试阶段误判。

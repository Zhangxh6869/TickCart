# TickCart 阶段二 · 商品分享功能实现方案

> 状态：**待评审**（本文只做设计，不含代码改动）
> 关联文档：《TickCart项目阶段划分.md》阶段 2、《秒杀商城开发计划.md》§商品详情页
> 参考图：商品详情页点「分享」后从底部升起的「分享至」面板（两行 5 列 + 取消）

---

## 1. 背景与目标

### 1.1 现状

商品详情页右上角已有分享入口，但只弹了一句占位提示：

```ts
// frontend/apps/mall/src/views/ProductDetailView.vue
function onShare() {
  showToast('分享功能将在阶段2开通')
}
```

### 1.2 目标

把该入口做成参考图那样的分享面板，并让每个选项**有真实行为**（而不是全都 toast）：

1. 面板本身与参考图对齐：标题「分享至」、两行 5 列图标、「取消」。
2. 9 个选项全部可用：微信 / 朋友圈 / QQ / QQ空间 / 新浪微博 / 复制链接 / 生成海报 / 举报 / 反馈与建议 / 更多。
3. 分享链接口径统一、可复用（后续首页卡片、秒杀页都能直接接）。
4. **不新增后端表、不改后端接口、不改路由结构**（默认方案）；不引入额外 npm 依赖（可选增强见 §9）。

### 1.3 非目标（本阶段不做）

- 微信 JS-SDK 定制分享卡片（需公众号 + 域名备案 + 后端签名接口，超出阶段 2 范围）。
- 分享埋点 / 邀请返利 / 分享记录统计（涉及建表，需你单独确认）。
- 原生 App 级分享（本项目是 H5）。

## 2. 技术选型（关键结论）

**直接使用 Vant 内置的 `van-share-sheet`，不自己写面板。**

理由（已核对 `vant@4.10.2` 源码 `es/share-sheet/`）：

| 需求 | Vant 现状 | 结论 |
|---|---|---|
| 面板结构 | 标题 + 选项网格 + 取消按钮，`v-model:show` | 与参考图结构一致 |
| 微信 / 朋友圈 / QQ / 微博 图标 | **内置** `wechat` `wechat-moments` `qq` `weibo`，且**自带品牌色圆形底**（`#0bc15f` / `#7bc845` / `#38b9fa` / `#ee575e`） | 无需准备任何图标素材 |
| 复制链接 / 生成海报 | `icon: 'link'` → `link-o`；`icon: 'poster'` → `photo-o` | 内置 |
| 举报 / 反馈与建议 / 更多 | `warning-o` / `edit` / `ellipsis` | 内置 |
| 自定义图片图标 | `icon` 含 `/` 时渲染为 `<img>` | 有需要时可用 `/img/...` |
| 选项可带样式钩子 | `option.className` 会挂到选项根节点 | 可覆盖单个选项配色 |

全局注册已就绪（`main.ts` 里 `app.use(Vant)`），**组件无需 import**。

### 2.1 唯一需要「改」的：布局从单行滚动 → 两行 5 列

Vant 默认 `.van-share-sheet__options` 是 `display:flex; overflow-x:auto`（**单行横向滚动**），而参考图是 **2 行 × 5 列**。必须用 CSS 覆盖（写在 `ShareSheet.vue` 的 scoped 样式里，用 `:deep()` 穿透）：

```css
:deep(.van-share-sheet__options) {
  flex-wrap: wrap;
  overflow-x: visible;
  row-gap: 16px;
}
:deep(.van-share-sheet__option) {
  flex: 0 0 20%;
  width: 20%;
}
/* 默认左右各 16px 外边距会把 48px 图标挤出 20% 栅格 */
:deep(.van-share-sheet__icon),
:deep(.van-share-sheet__image-icon) {
  margin: 0;
}
```

### 2.2 唯一没有内置图标的：QQ空间

Vant 无 qzone 图标。**不新增图片素材**，用「星形图标 + 自定义配色」复刻参考图的黄色方块：

```ts
{ name: 'QQ空间', icon: 'star-o', className: 'share-opt--qzone' }
```
```css
:deep(.share-opt--qzone .van-share-sheet__icon) {
  background-color: #f7b500;
  color: #fff;
  font-size: 30px;
}
```

> 若你更希望用真实 QQ空间 logo，则需往 `imgs/share/` 放一张 PNG（涉及品牌素材来源，需你提供）。

### 2.3 可选样式微调（对齐参考图，等你确认）

- 第二行图标底：参考图是**浅灰/白底 + 细描边**，Vant 默认 `--van-gray-2` 灰底。可覆盖为白底 + 1px 边框。
- 第二行图标字号：Vant 只给 link/poster/qrcode 设了 26px，`warning-o`/`edit`/`ellipsis` 会退到默认 16px，**偏小**，建议统一 24px。
- 「取消」：参考图是带左右留白的圆角白块，Vant 默认整宽 + 上方 8px 灰缝。可覆盖为圆角块。

## 3. 分享链接口径

统一由 `utils/share.ts` 产出，**禁止各处手写字符串**（与 `utils/checkout-route.ts` 的约定风格保持一致）：

```ts
/** 商品分享链接：当前站点 origin + 详情页路径。origin 取运行时值，本地/线上自动适配。 */
export function buildProductShareUrl(productId: number): string {
  return `${window.location.origin}/products/${productId}`
}
```

- 不追加 `?share=1` 之类参数：阶段 2 无埋点消费方，加了反而污染 URL 语义。将来要做来源统计时，在这里加一个可选参数即可，调用方不用改。
- 链接是 **SPA 路由**，依赖 nginx（阶段 4）配 `try_files ... /index.html` 兜底，否则直接打开分享链接会 404。**这一点必须写进阶段 4 的部署清单**。

## 4. 交互行为矩阵（逐项）

| 选项 | 行为 | 依赖 |
|---|---|---|
| **微信** | 微信内 → 弹「点右上角 ··· 分享给朋友」引导蒙层；微信外 → toast「请复制链接后在微信中打开」 | UA 判断 |
| **朋友圈** | 同上，文案改为「分享到朋友圈」 | UA 判断 |
| **QQ** | 新窗口打开 QQ 官方分享页 `connect.qq.com/widget/shareqq/index.html?url=&title=&desc=` | 无 |
| **QQ空间** | 新窗口打开 `sns.qzone.qq.com/cgi-bin/qzshare/cgi_qzshare_onekey?url=&title=&summary=&pics=` | 无 |
| **新浪微博** | 新窗口打开 `service.weibo.com/share/share.php?url=&title=&pic=` | 无 |
| **复制链接** | `navigator.clipboard.writeText` → 失败降级 `document.execCommand('copy')`；成功 `showToast('链接已复制')` | 见 §5.2 |
| **生成海报** | Canvas 绘制商品海报（图 + 标题 + 价格 + 二维码）→ 弹层预览 → 长按保存 / 下载按钮 | 见 §5.3 |
| **举报** | `van-action-sheet` 选原因（虚假宣传 / 价格欺诈 / 禁售商品 / 其他）→ 提交 → toast「举报已提交」 | 纯前端（可选落库见 §9） |
| **反馈与建议** | `van-dialog` + 文本域 → 提交 → toast「感谢反馈」 | 纯前端（可选落库见 §9） |
| **更多** | 优先 `navigator.share({title, text, url})`；不支持则 toast「请使用浏览器菜单分享」 | Web Share API |

### 4.1 三个必须遵守的判定规则

1. **微信内置浏览器（`/micromessenger/i.test(ua)`）里，QQ / QQ空间 / 微博 的分享页域名会被拦截**，打开是白屏。
   → 因此：**只要在微信内，除「复制链接 / 生成海报 / 举报 / 反馈」外的所有跳转渠道，一律改为走引导蒙层**，不要尝试开新窗口。
2. **引导蒙层只对微信内有效**（在微信外引导「点右上角」是错的）。
3. `navigator.share` / `navigator.clipboard` 都要求**用户手势**上下文，必须在 `select` 回调里同步调用，不能包 `setTimeout`。

## 5. 关键实现细节

### 5.1 微信内引导蒙层（`ShareGuide.vue`）

半透明黑底 + 右上角箭头（可用 CSS 画，或 Vant 图标 `arrow-up` 旋转 45°）+ 两行文案：

> 点击右上角「···」
> 选择「发送给朋友」/「分享到朋友圈」

整屏可点关闭，`v-model:show` 与面板联动：选中「微信/朋友圈」时**先关面板、再开蒙层**（避免两个 popup 同时在场）。

### 5.2 复制链接（含降级）

```ts
export async function copyText(text: string): Promise<boolean> {
  // 现代 API：要求安全上下文（https / localhost）。生产 http 部署会不可用，必须有降级。
  if (navigator.clipboard && window.isSecureContext) {
    try {
      await navigator.clipboard.writeText(text)
      return true
    } catch {
      /* 落到下面的降级分支 */
    }
  }
  // 降级：临时 textarea + execCommand（微信 webview 里这条通常有效）
  const el = document.createElement('textarea')
  el.value = text
  el.setAttribute('readonly', '')
  el.style.cssText = 'position:fixed;top:-9999px;opacity:0'
  document.body.appendChild(el)
  el.select()
  el.setSelectionRange(0, text.length)
  let ok = false
  try {
    ok = document.execCommand('copy')
  } catch {
    ok = false
  }
  document.body.removeChild(el)
  return ok
}
```

失败时提示「复制失败，请长按链接手动复制」——**不要静默失败**。

### 5.3 生成海报（`SharePoster.vue` + `utils/poster.ts`）

绘制流程（纯前端 Canvas，无后端）：

```
createCanvas(750 × 1200)
  ├─ 白底圆角卡片
  ├─ 商品主图（object-fit: cover 手动画，2 倍图下采样更清晰）
  ├─ 标题（最多 2 行，超出省略号，手写换行逻辑）
  ├─ 价格（¥ + 整数大字 + 小数小字，与详情页版式一致）
  ├─ 二维码（指向分享链接）+ 「长按识别二维码」
  └─ 底部品牌文案
→ canvas.toDataURL('image/png')
→ 弹层 <img> 预览 + 「长按图片保存到相册」+ <a download="tickcart-{id}.png"> 下载
```

三个硬约束：

1. **图片必须同源**，否则 canvas 被污染、`toDataURL()` 抛 `SecurityError`。本项目商品图全部是 `/img/**`（同源，两个 dev server 都代理了），**安全**。将来若接入外链图，必须加 `img.crossOrigin = 'anonymous'` + 后端 CORS。
2. **图片加载失败不能让海报整体失败**：`img.onerror` 时退化为纯色占位块 + 商品名，海报仍可生成。
3. 绘制前 `await` 图片 `onload`；`toDataURL` 用 `image/png`。

二维码生成（**实施结论：用零依赖的 `qrcode-generator`**）：

- **选用 `qrcode-generator@2.0.4`**（MIT，`dependencies: {}` —— 真正的零传递依赖），它提供 `renderTo2dContext(ctx, cellSize)`，可以把二维码**直接画到海报画布上**，不产生中间图片、不经过 img 解码，也就没有 canvas 污染问题；`cellSize` 取整还能保证不糊。
- 为什么不用更常见的 `qrcode`（node-qrcode）：它会连带拉进 31 个传递依赖（yargs / pngjs / dijkstrajs …）以及 `@types/qrcode` → `@types/node`，而 `@types/node` 一旦进树就会改变 vite 的 peer 解析快照（`vite@5.4.21(@types/node@26.6.5)`），进而扰动本项目「只允许存在 2 条既有类型错误」的基线。为了一个二维码付这个代价不划算。
- 备选（已否决）：后端 `GET /api/share/qrcode?text=` + zxing —— 要新增 maven 依赖与新模块，比前端加一个零依赖包重得多。

### 5.4 渠道跳转的 URL 编码

所有渠道 URL 的 `url` / `title` / `pic` 参数**必须 `encodeURIComponent`**；`title` 建议带商品名，`pic` 用商品主图的**绝对地址**（`origin + mainImage`），相对路径第三方抓不到。

## 7. 组件接口设计

```ts
// ShareSheet.vue
defineProps<{
  show: boolean
  product: { id: number; name: string; mainImage: string | null }
}>()
defineEmits<{
  'update:show': [boolean]
  /** 内部已处理完的渠道（复制链接/生成海报/举报/反馈/更多）向外抛，便于将来埋点 */
  handled: [channel: string]
}>()
```

- 面板**只负责「选项 → 动作」的分发**，具体动作委托给 `utils/share.ts` 与两个子弹层。
- 商品信息用 `product` 对象传入（不传整个 `ProductDetail`），组件因此能直接被首页卡片 / 秒杀页复用。

## 8. 验收标准与测试

### 8.1 手工验收

1. 详情页点分享 → 底部升起「分享至」面板，**两行 5 列**，图标与文案与参考图一致。
2. 点「复制链接」→ toast 提示，粘贴到浏览器地址栏能打开该商品详情页。
3. 点「生成海报」→ 海报图片正常渲染（商品图 + 标题 + 价格 + 二维码），二维码扫出来是分享链接。
4. 桌面 Chrome（非微信）点「微信」→ 提示复制链接；微信内打开点「微信」→ 出现右上角引导蒙层。
5. 「取消」和遮罩点击都能关闭面板；连续开关多次不残留。
6. 未登录也能分享（分享是浏览态行为，**不挂 `requiresAuth`**）。

### 8.2 自动化回归（`scripts/verify-share.mjs`，CDP）

纯读操作、**不产生任何写请求**，无数据污染风险。断言点：

| 段 | 断言 |
|---|---|
| A | 进入某商品详情页（动态取一个 id，取不到 SKIP），`.nav__btn[aria-label="分享"]` 存在且可点 |
| B | 点击后 `.van-share-sheet` **可见**（★ 必须读 `getComputedStyle(el).display !== 'none'`，Vant popup 关闭后 DOM 仍在） |
| C | 选项文案断言表：`['微信','朋友圈','QQ','QQ空间','新浪微博','复制链接','生成海报','举报','反馈与建议','更多']` 全在 |
| D | 布局断言：`.van-share-sheet__option` 数量 = 10，且第 1 个与第 6 个 `offsetTop` 不同（确认换行成两行） |
| E | 点「复制链接」→ 读 `navigator.clipboard.readText()`（或注入桩）校验等于 `origin + /products/{id}` |
| F | 点「生成海报」→ 等 canvas 出现 → 断言 `toDataURL().length > 5000` 且非纯白（抽样像素） |
| G | 点「取消」→ 面板 `display === 'none'` |

★ 沿用项目既有约定：**断言前必须做双条件判定**（`display` + 文本），按钮文案不匹配时 `click()` 会静默失败，点击后必须断言上下文，不符即 `throw`。

### 8.3 构建校验

```bash
pnpm --filter mall exec vue-tsc --noEmit   # 只应剩 utils/request.ts、vite.config.ts 两条既有错误
pnpm --filter mall exec vite build
```

## 10. 风险与规避

| 风险 | 影响 | 规避 |
|---|---|---|
| 微信内无法唤起原生分享（H5 平台限制） | 用户以为坏了 | 引导蒙层兜底，文案明确 |
| 微信内置浏览器不支持 `navigator.clipboard` | 复制失败 | `execCommand` 降级 + 失败提示 |
| 生产 http 部署导致 `isSecureContext = false` | 现代剪贴板 API 全废 | 同上降级；阶段 4 建议上 https |
| 商品图为外链时 canvas 被污染 | 海报生成抛异常 | 当前全部同源；加 `onerror` 兜底；未来接外链需 CORS |
| 直接打开分享链接 404 | 分享形同虚设 | 阶段 4 nginx 配 `try_files ... /index.html`（已写入部署清单） |
| `qrcode` 依赖引入 | 与「不加依赖」原则冲突 | 列为决策点 1，等你确认 |

### 过程中踩到的两个坑（已记入长期记忆）

1. **`pnpm install` 在本机会把 lockfile 写坏**：pnpm 12.9.1 把「它自己」的 lock 块（`importers` / `packages` / `snapshots` / `settings`）整段拼到文件最前面，于是出现**两个顶层 `importers:` 键**，工作区项目全落到第二个里 —— pnpm 之后就读不到它们，直接判定「Already up to date」并跳过链接。本次是手工按最小 diff 把 `qrcode-generator` 补进 lockfile 的（9 行），并手工补回 junction 链接。
2. **微信内的引导蒙层在截图里看不出来**：`van-overlay` 是淡入的，截早了会拍成半透明；判定「有没有压暗页面」不能靠肉眼看截图，要用 CDP 截图 + 页面内 canvas 取真实像素（实测 `rgb(76,76,76)` = 255×0.3，即 70% 黑遮罩生效）。
